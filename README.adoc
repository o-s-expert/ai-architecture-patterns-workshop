= AI Architecture Patterns Workshop
:toc:
:toclevels: 2

A hands-on workshop on integrating AI capabilities into enterprise applications with Enterprise Java, LangChain4j, and CDI.

== Workshop Website

https://o-s-expert.github.io/ai-architecture-patterns-workshop/[Open Workshop Website]

== Overview

The workshop (about 4 hours) explores key AI architecture patterns through five progressive labs that share a consistent scenario.

== Technology Stack

* Java 21 and Apache Maven
* CDI and MicroProfile
* LangChain4j
* Google Gemini
* MkDocs Material (documentation website)

== Maven Project

The project is a single-module Maven build (`os.expert:ai-architecture-patterns-workshop`) that targets *Java 21* and runs on Java SE through CDI, without an application server.

* *LangChain4j* (AI Services, memory, structured outputs, tools, RAG) and the *Google Gemini* integration
* *CDI* with *Weld SE*, plus the LangChain4j CDI portable extension
* *MicroProfile Config* (SmallRye Config) configured in `src/main/resources/META-INF/microprofile-config.properties`
* A local embedding model and in-memory embedding store for the RAG lab, so no database is required

Each lab has its own package under `src/main/java/os/expert/`:

[cols="1,2"]
|===
|Package |Lab

|`os.expert.lab1` |DAG: Book Recommendations
|`os.expert.lab2` |Conversational Memory
|`os.expert.lab3` |Retrieval-Augmented Generation
|`os.expert.lab4` |Reflection Architecture
|`os.expert.lab5` |Planning Architecture
|===

NOTE: Labs 1 and 2 are complete tutorials; Labs 3-5 are under development.

=== Lab 0: Configuration Check

`os.expert.lab0.App` is a standalone Java SE entry point that verifies the setup end to end: Weld SE starts, LangChain4j CDI registers the declarative `AssistantService`, and Gemini answers two prompts. It has no REST endpoint or web server.

==== Gemini API Key

. Create a key in https://aistudio.google.com/api-keys[Google AI Studio].
. Copy the template and edit it. `.env` is ignored by Git; never commit it.
+
[source,bash]
----
cp .env.example .env
# then set GEMINI_API_KEY in .env
----

SmallRye Config reads `.env` from the working directory, so run from the repository root. A real `GEMINI_API_KEY` environment variable takes precedence over the file. The model is configured in `microprofile-config.properties` (currently `gemini-3.5-flash`).

==== Run from IntelliJ IDEA

Open the project as a Maven project with a Java 21 SDK, then use the shared run configuration *Lab0 App* (main class `os.expert.lab0.App`, working directory `$PROJECT_DIR$`).

==== Common errors

* *HTTP 400/403 or "API key not valid"*: `GEMINI_API_KEY` is missing, a placeholder, or wrong; check `.env`.
* *`.env` not loaded*: the working directory is not the repository root.
* *HTTP 404 for a model*: the model is not available to your key (for example `gemini-2.5-flash` for new users). List models with the `models` API and update `model-name`.
* *HTTP 429/503 or "request timed out"*: rate limit or high demand on that model; retry later or try another model. Weld startup takes about a second, so long delays come from the API request.

== Website Deployment

The workflow `.github/workflows/deploy-docs.yml` builds the site with `mkdocs build --strict` and publishes it to GitHub Pages using GitHub Actions on every push to `main`, or manually through `workflow_dispatch`. Generated output (`site/`) is not committed.
